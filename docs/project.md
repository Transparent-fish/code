## 背景

现在整个仓库的体积是 3.2GB 算比较大了，可以考虑压缩一下了？

## 方案

emmm，我想了两种思路：

#### Plan A

因为老项目之前是没有上传大小限制的，所以仓库里存在很多体积巨大的图片（eg: A/abc123），我们可以用像是 `micropng-cli` 这种 CLI 工具把所有体积大于等于 1Mb 的图片压缩到 1Mb 一下，并去除 EXIF 信息。

效果

##### befor

```

PS C:\Users\PC\Downloads\abc123> ls


    目录: C:\Users\PC\Downloads\abc123


Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a----        2026-08-14      9:55        1284965 IMG_20180726_084103.jpg
-a----        2026-08-14      9:55         466719 IMG_20180728_165450.jpg
-a----        2026-08-14      9:55         507273 IMG_20180807_165627.jpg
```

##### End

```
PS C:\Users\PC\Downloads\abc123\compressed> ls


    目录: C:\Users\PC\Downloads\abc123\compressed


Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a----        2026-08-14     10:29         887100 IMG_20180726_084103.jpg
-a----        2026-08-14     10:29         444959 IMG_20180728_165450.jpg
-a----        2026-08-14     10:29         518170 IMG_20180807_165627.jpg
```

可以看到是明显的减少了很多体积的

##### 优点：

操作方便，速度较快？压缩效果较好

##### 缺点

改的文件巨多，Review 难度大

#### Plan B

把整个项目迁移到 Git LFS，整个仓库只保留由 LFS 管理的指针文件

##### 优点

整个项目体积预计小于等于 50Mb

##### 缺点

迁移难度巨大，对后来的贡献值及其不方便
